3Check an email you already have

How to read the labels. Published the address appears verbatim on a page you pointed at, or on the person's public GitHub. A company's own site or the person's own profile is a stronger source than an aggregator repeating an address. Verified a connected verification API confirmed the mailbox. Only possible once the optional backend and an API key are set up. Seen publicly the exact address appears publicly (Gravatar profile or PGP key). Proof of past public use, not of current deliverability or employer. Unverified guess generated from common corporate patterns; the domain accepts mail, nothing more. No candidate is presented as the best email without address-specific evidence. Inconclusive the checks could not say either way. Unlikely the domain has no mail records.

Honest limits. MX records show a domain accepts mail; they cannot detect catch-all domains, and this tool does not claim to. Mailbox-level confirmation needs a verification API (Hunter and others), which plugs into the backend worker in this repo when you add a key. A name read from a LinkedIn URL slug is a guess you can edit, never a verified identity.

Privacy: what leaves your browser. The app stores nothing and uses no account, but checks do talk to outside services: the domain goes to a public DNS resolver (Cloudflare), the company name to Clearbit, a hash of each top candidate to Gravatar, top candidates to the PGP keyserver, the name to GitHub search, and a scanned page's URL to a public reader relay (r.jina.ai, fallback allorigins). Private or internal URLs and URLs containing credentials are refused before any relay is used. LinkedIn is never fetched or scraped.
